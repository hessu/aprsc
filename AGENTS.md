# AGENTS.md — working in the aprsc source tree

aprsc is an APRS-IS server written in C for core and Tier2 servers of the
amateur radio APRS Internet System. It is a small, fast, multi-threaded
daemon. This file orients a coding agent: where things live, how to build and
test, and which conventions the maintainer enforces. The human-oriented docs
in `doc/` remain authoritative; read `doc/CONTRIBUTING.md` and
`doc/DESIGN.md` before changing anything non-trivial.

## Repository layout

```
src/        All C sources, the autoconf build, packaging, and the web status UI
tests/      Functional test suite in Go (runs the real binary against fake peers), and the configs it uses
doc/        Markdown documentation published to he.fi/aprsc (also installed as HTML)
tools/      Standalone Perl helpers for feeding, copying and receiving APRS-IS traffic
build/      build-all.pl: maintainer script that builds packages in LXD VMs per distro
.github/    CI workflow: configure, make, make testinstall, make test, on Ubuntu with and without IS2
```

There is no top-level Makefile. Everything is driven from `src/` and `tests/`.

### src/ — key areas

`src/README.sources` describes every C file; keep it updated when adding files.
The summary below groups them by role.

**Process and threads**

| File | Role |
|------|------|
| `aprsc.c` | `main()`, command line, signals, daemonising, chroot/setuid, live upgrade (SIGUSR2 re-execs the binary, SIGUSR1 reloads config), starts all threads |
| `accept.c` | Accept thread: listeners (TCP/UDP/SCTP/TLS), ACL checks, hands new clients to the least loaded worker |
| `worker.c` / `worker.h` | Worker threads: socket I/O, parsing, outbound filtering. `worker.h` defines `struct client_t`, `struct pbuf_t`, `struct worker_t` and is the place to start reading |
| `dupecheck.c` | Dupecheck thread: 30-second duplicate cache; sorts packets into `pbuf_global` and `pbuf_global_dupe` queues |
| `uplink.c` | Uplink thread: connects to upstream servers, handles the login handshake, then hands the socket to a worker |
| `http.c` | HTTP thread (libevent2): serves `/status.json`, static files from `web/`, and HTTP position uploads |
| `status.c` | Builds the status JSON consumed by the web UI and the munin plugin |

Thread names set with `thread_name_set()` are `aprsc time`, `aprsc accept`,
`aprsc dupecheck`, `aprsc uplink`, `aprsc http`, and one per worker.

**Packet pipeline (inside a worker)**

| File | Role |
|------|------|
| `login.c` | `login_handler()` for the `user ... pass ...` command, passcode and TLS cert validation |
| `incoming.c` | `incoming_handler()`: line to `pbuf_t`, calls q-construct and APRS parsers, drop reasons (`INERR_*`) |
| `parse_qc.c` | q-construct (`qAC`, `qAR`, ...) algorithm |
| `parse_aprs.c` | Minimal APRS parser, enough for filtering (position, type, symbol); ported from Ham::APRS::FAP |
| `outgoing.c` | Walks the global queues and sends to clients through the filter chain |
| `filter.c` | APRS-IS filter language (`m/`, `r/`, `t/`, `b/`, `f/`, ...) |
| `messaging.c` | Helpers for APRS text messages generated by the server |
| `clientlist.c` | Global list of logged-in callsigns for duplicate-login and q-construct lookups |
| `client_heard.c` | Per-client heard and courtesy lists for message routing |
| `historydb.c` | Last-position cache used by the `f/` friend filter and similar |

**IS2 (binary protocol, work in progress on this branch)**

| File | Role |
|------|------|
| `aprsis2.proto` | Protocol Buffers v3 schema. Edits here regenerate `aprsis2.pb-c.[ch]` via `protoc-c` at build time; the generated files are not committed and are removed by `make clean` |
| `aprsis2.c` | IS2 framing (STX + reserved byte + 16-bit length + body + ETX), login, ping, buffering, UDP peergroup negotiation, HMAC signatures, frame loss tracking |
| `aprsis2plain.c` | Parses `#is2-meta` key-value metadata lines from plaintext clients into IS2 fields |
| `doc/IS2PEERING.md` | The UDP peering handshake spec |

**Infrastructure and libraries**

| File | Role |
|------|------|
| `config.c` / `config.h` | Config file parsing, validation, reload, and all global configuration variables. `config.h` also selects feature macros (`USE_SCTP`, `USE_POSIX_CAP`, `USE_CLOCK_GETTIME`) |
| `cfgfile.c` | Generic keyword-driven config parser used by `config.c` |
| `tls.c` / `tls.h` | OpenSSL TLS for listeners and uplinks, client cert auth. `USE_SSL` is defined unconditionally in `tls.h` |
| `sctp.c` | SCTP socket setup, compiled only when `USE_SCTP` is set |
| `xpoll.c` | Wrapper over `poll()` and `epoll()`; `XP_USE_EPOLL` is chosen in `xpoll.h` |
| `hlog.c` | Logging to stderr, syslog or rotated file. Use `hlog(LOG_x, fmt, ...)`; `hlog_packet()` logs a packet alongside |
| `hmalloc.c` | `hmalloc`, `hrealloc`, `hfree`, `hstrdup`. Use these, never bare `malloc` |
| `cellmalloc.c` | Slab allocator for hot structures. Compiling with `-D_FOR_VALGRIND_` swaps it for `hmalloc` so valgrind can see individual allocations |
| `counterdata.c` | Periodic counter samples for status page graphs |
| `cJSON.c` | Vendored JSON library (third-party style, spaces not tabs) |
| `acl.c`, `keyhash.c`, `netlib.c`, `passcode.c`, `random.c`, `rwlock.c` | Small self-contained utilities |
| `inet_ntop.c`, `inet_pton.c`, `getnameinfo.c`, `gai_strerror.c` | Fallbacks linked only when libc lacks them (via `@LIBOBJS@`) |

**Other things under src/**

- `web/` — static status page: AngularJS app (`aprsc.js`), flot graphs, `strings-*.json` translations. No build step; files are copied verbatim.
- `debian/`, `rpm/` — packaging. Both systemd units and SysV init scripts live here.
- `aprsc.conf` — example config installed to `/opt/aprsc/etc/`. Note the deliberate `MagicBadness` line that forces admins to edit it.
- `aprsc_munin`, `aprsc-prepare-chroot.sh` — installed alongside the binary.
- `tools/` — ad hoc load generators (`eventload.c`, `floodconnect.c`) and a Coverity submit script. Not part of the build.
- `VERSION` — the release version. `version_branch.h` — leave `VERSION_BRANCH ""` in commits.

## Building

Dependencies: GCC or clang, GNU make, libevent2, OpenSSL >= 1.1.1,
protobuf-c and `protoc-c`, and optionally libcap, libsctp, zlib. The
CI job in `.github/workflows/tests.yml` has the exact apt package list.

```sh
cd src
./configure            # macOS with MacPorts: CFLAGS=-I/opt/local/include LDFLAGS=-L/opt/local/lib ./configure
make -j4
```

- `configure` is generated from `configure.ac` with `autoconf`; the generated
  `configure` script is committed, so regenerate and commit it if you change
  `configure.ac`. `Makefile.in` and `ac-hdrs.h.in` are the templates;
  `Makefile`, `ac-hdrs.h`, `config.status` and `config.log` are build output.
- Default `CFLAGS` add `-Wall -Wstrict-prototypes -D_REENTRANT`. Keep the
  build warning-free.
- `make valgrind` rebuilds with `-D_FOR_VALGRIND_`; `make profile` with `-pg`.
  Run `make clean` first in both cases.
- `make install` installs into `/opt/aprsc` (binary, man page, web files,
  example config). `make make-deb` builds a Debian package. `make dist` and
  `make install-webdoc` are maintainer-only.
- Version strings come from `VERSION` plus `git describe` and are written to
  `version_data.h` on every build.

## Testing

The test suite is functional: each test starts the real `aprsc` binary with a
config from `tests/cfg-aprsc/`, connects fake APRS-IS clients, upstreams and
UDP peers to it, and asserts on what comes out. There are no C unit tests.
The suite is written in Go, in `tests/go/`; it replaced an earlier Perl suite
in 2026, and each test's header comment names the Perl test it was ported
from.

```sh
cd src && make testinstall      # copies web/ files into tests/web, creates tests/data
cd ../tests
make test                       # all of it; generates the TLS test CA and certs on first run
make test PARALLEL=1            # one test at a time (default 3)
make test-short                 # skips the heavy TestUDPLoad
make test-race                  # with the race detector
make test-run T=TestDupecheck   # one test or a group, verbose (T is a regexp)
```

Go dependencies: Go 1.26 or newer, and `github.com/hessu/go-aprs-fap` for
the APRS parser and the `Conn` type behind the plaintext client. Go modules
are fetched on first use. Subtests can be run with
`go test -run 'TestDupecheck/long_dupe'` in `tests/go/`, once
`make tls-testcert` has been done in `tests/`; see `tests/go/README.md`.

IS2 is compiled out unless aprsc was configured with `--enable-is2`. The IS2
tests (`TestIS2*`, `TestDupeClientIS2`, `TestLiveUpgrade`) skip themselves on
a build without it, and `TestIS2Disabled` does the opposite. Run them with
`APRSC_BIN=/path/to/aprsc make test`. The Go IS2 types are generated from
`src/aprsis2.proto`: after changing the schema, run
`go generate ./internal/aprsis2` in `tests/go/` (needs `protoc` and
`protoc-gen-go`) and commit the result; `TestGeneratedIsCurrent` fails
otherwise.

How the suite is structured:

- `tests/go/internal/harness` starts and stops the server. It runs aprsc
  with a copy of the config in a temp dir of its own, together with its log
  (`-e debug -o file -r <temp dir>`, so a failed test prints the tail of
  it), pid file and `RunDir`. It waits for the log to say the listeners are
  open, and the HTTP ports too when the config has them. It runs with
  `tests/` as the working directory, because the configs use relative
  paths. `TEST_PRODUCT=javap` or `javap4` runs the tests against
  javAPRSSrvr if a copy is present in `tests/javaprssrvr/` (not distributed);
  tests of aprsc-only features skip.
- Tests run in parallel, `PARALLEL` (default 3) at a time, each with a
  server of its own on ports of its own. Every test starts with
  `harness.Parallel(t)` and gets its addresses from `harness.Addr(t, 55152)`,
  `harness.AddrOn(t, "127.0.0.1", 10153)` or `harness.Port(t, 51342)`, using
  the port numbers of the configs; never from literal ports. The harness
  maps those numbers to a block of ports in the 20000 range per running
  test, below the ephemeral port range, and rewrites the server's config
  copy to match, so the configs keep their fixed numbers. A port number new
  to the configs must be added to the table in
  `tests/go/internal/harness/ports.go`.
- `tests/go/internal/isclient` has the clients: `Connect` (plaintext, built on
  the go-aprs-fap `Conn`), `ConnectIS2`, `ConnectUDP`, `FakeUpstream` for
  uplinks the server connects to, and `UDPPeer` and `IS2Peer` for UDP
  peers. `TxRx` (send on one connection, expect on another) and
  `ExpectDrop` (send a packet that must be dropped followed by a helper
  packet that must arrive) are the assertions, and `Step` with `RunSteps`
  runs a table of them as subtests. Reads always have deadlines; avoid
  sleeps, and prefer waiting for a reply the server sends (`SetFilter` waits
  for the `# filter ... active` line).
- Cases that share server state (the dupe cache, heard lists) run in order
  within one test; subtests are not parallel.
- Test files are named by area: login and start-up, dupecheck and drops,
  quirks and third-party, q constructs, filters, messaging, load and
  uplinks, UDP/HTTP/SCTP/status, live upgrade, IS2, aggregator.
- Port map used by the configs in `tests/cfg-aprsc/`: `55152` full feed,
  `55580` igate, `55581` client-only, `55153` dupefeed, `55080` UDP submit,
  `55154`, `55582` and `55583` TLS variants, `56xxx` IS2 equivalents,
  `55501` HTTP status, `10153` and `57153/57154` fake upstreams, `1640x`
  UDP peers. `tests/cfg-javap/` has the javAPRSSrvr equivalents.

Every new feature must come with a test. Run the full suite before
connecting modified code to the live APRS-IS network.

## Code conventions

These come from `doc/CONTRIBUTING.md` and from the existing code.

- **Indent with one tab**, displayed as 8 spaces. Linux kernel style:
  function opening brace on its own line, `if (...) {` on the same line,
  `type *name` pointer spacing. Vendored third-party files (`cJSON.c`,
  `tls.c` derived from nginx, the libc fallbacks) keep their own style.
- **Never reformat or reindent code** you are not functionally changing.
  Diffs should show only the functional change.
- Every source file starts with the aprsc copyright and BSD license header
  block, followed by a short comment saying what the file does.
- C99-ish C with pthreads. Autoconf results come from `ac-hdrs.h`, usually
  pulled in through `config.h`. Define `_GNU_SOURCE` before system headers
  where needed.
- Memory: `hmalloc`/`hfree`/`hstrdup` for general allocation,
  `cellmalloc` arenas for high-volume fixed-size objects. Any new
  cellmalloc user needs a `#ifndef _FOR_VALGRIND_` fallback like the
  existing ones.
- Logging: `hlog(LOG_DEBUG|INFO|WARNING|ERR|CRIT, ...)`. Prefix
  client-related messages with the client address, as `login.c` does.
- Time: use the globals `now` (wall clock) and `tick` (monotonic) instead of
  calling `time()`; the time thread refreshes them several times a second.
- Error paths use `goto` cleanup labels and negative `INERR_*` codes for
  packet drops. When adding an `INERR_*` constant in `worker.h`, also update
  `INERR_MIN`, the `inerr_labels[]` array in `incoming.c`, and the
  `RXERR_*` strings in `web/aprsc.js` and `web/strings-en.json`.
- Threading: worker-local data needs no locks; shared structures are
  protected by the mutex or `rwlock_t` next to them in `worker.h`. Transfers
  between threads batch many packets or clients per lock acquisition. Avoid
  adding new contention on the hot path.
- Design rule: it is an APRS-IS server, not an igate, beacon generator or
  database. Feature requests that belong in igate software are declined.
- Do not bump `VERSION`; the maintainer does that at release time.
- Keep `src/README.sources` and the relevant `doc/*.md` in sync with
  structural changes. `doc/CONFIGURATION.md` documents every config
  keyword; update it when adding one to `config.c`.

## Git conventions

- Branches: `main` is the integration branch. Feature work happens on
  `feature/<name>` and fixes on `bugfix/<name>`. Releases are tagged
  `vX.Y.Z`.
- Commit subjects are short imperative lines, usually prefixed with the
  area touched, e.g. `IS2: Detect lost IS2 frames on corepeer links`,
  `uplink: Fix segfault when failing to parse server signature`,
  `tests: Add IS2 udp-peer and optional field tests`.
- Do not add `Co-Authored-By` trailers.
- Contributions arrive as GitHub pull requests against `main`.

## Runtime notes useful when debugging

- Command line: `aprsc [-t chrootdir] [-u user] [-c cfgfile] [-f] [-n logname] [-e loglevel] [-o logdest] [-r logdir] [-p pidfile] [-y]`. `-y` parses the config and exits.
- Status JSON is at `http://host:14501/status.json` in production, port
  `55501` under test. The munin plugin and the web UI both read it.
- The daemon chroots to `/opt/aprsc` and drops privileges, so all paths in
  the config are relative to that directory in production.
- `doc/DEBUGGING.md` covers enabling debug logging and core dumps.
